# schedule-service — готовый проект к ЛР №3

Всё уже написано: осталось создать аккаунты (GitHub, Supabase, Vercel, бот в Telegram)
и вставить туда свои ключи/токены. Ниже — куда именно что кладётся.

## Структура

```
schedule-service/
├── schema.sql              → вставить в Supabase (SQL Editor)
├── frontend/                → это то, что заливается на Vercel
│   ├── index.html
│   ├── style.css
│   ├── config.js            → сюда вписать SUPABASE_URL и SUPABASE_ANON_KEY
│   └── script.js
└── bot/                      → это то, что запускается на своём компьютере/сервере
    ├── bot.js
    ├── package.json
    └── .env.example          → скопировать в .env и вписать токены
```

## 1. Supabase (База Данных)

1. Зайдите на supabase.com → New project.
2. Слева откройте **SQL Editor** → New query → вставьте весь файл `schema.sql` → **Run**.
   Это создаст таблицы `groups` и `schedule` и сразу заполнит их вашим реальным
   расписанием группы **ПО-33** (без имён преподавателей — только предмет и кабинет).
3. В пятницу на исходном фото расписание обрезано снизу (не видно 5–6 пары) —
   зайдите в **Table Editor → schedule** и при необходимости добавьте недостающие строки.
4. Откройте **Project Settings → API** — оттуда возьмёте `Project URL` и `anon public key`
   для шагов 2 и 3.

## 2. Веб-сайт (Frontend → Vercel)

1. Откройте `frontend/config.js` и впишите свои значения:
   ```js
   const SUPABASE_URL = "https://ваш-проект.supabase.co";
   const SUPABASE_ANON_KEY = "ваш-anon-key";
   ```
2. Загрузите папку `frontend/` в ваш GitHub-репозиторий (в ветку `feature/frontend`,
   как требует задание) через GitHub Desktop: **Commit → Push origin**.
3. На vercel.com → **New Project** → подключите репозиторий → в настройках выберите
   ветку `feature/frontend` → Deploy.
4. Сайт сам подтягивает список групп, показывает расписание на сегодня и определяет,
   какая пара идёт прямо сейчас (это и есть логика `/today` и `/now` из задания).

## 3. Telegram-бот

1. В Telegram напишите **@BotFather** → `/newbot` → получите токен.
2. В папке `bot/`:
   ```bash
   cp .env.example .env
   ```
   и впишите в `.env`:
   ```
   BOT_TOKEN=токен_от_BotFather
   SUPABASE_URL=https://ваш-проект.supabase.co
   SUPABASE_ANON_KEY=ваш-anon-key
   ```
3. Установите зависимости и запустите:
   ```bash
   npm install
   npm start
   ```
4. В боте: `/start` → выбрать группу кнопкой → дальше `/today` и `/now`.

## 4. Git (для чек-листа сдачи)

1. Разработчик 1 создаёт репозиторий `schedule-service` на GitHub, добавляет
   Разработчика 2 в Collaborators, клонирует к себе через GitHub Desktop.
2. Разработчик 2 клонирует репозиторий, создаёт ветку `feature/frontend`
   (Current Branch → New Branch → Publish branch) и работает в ней над `frontend/`.
3. Разработчик 1 работает в `main` над `bot/`.
4. Когда фронтенд готов — Pull Request → Разработчик 1 проверяет и жмёт **Merge**.
5. Нужно минимум 4 коммита в истории репозитория.

## Как проверить, что всё работает (по критериям ЛР)

- Поменяйте `subject_name` какой-нибудь пары прямо в Supabase (Table Editor) —
  обновление должно появиться и на сайте (после обновления страницы), и в ответе
  бота на `/today`, без правок кода.
- В разное время дня спросите `/now` — бот и сайт должны корректно показывать
  "идёт пара" / "перемена" / "пары закончились".

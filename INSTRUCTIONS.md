## Часть 2. GitHub-репозиторий

🔲 **Разработчик 1 (если работаете в паре — иначе делаете всё сами):**

1. Зайдите на [github.com](https://github.com) → **New repository**.
2. Название: `schedule-service`. Поставьте галочку **Add a README file**.
3. **Create repository**.
4. Если работаете вдвоём: **Settings → Collaborators → Add people** →
   добавьте напарника по его GitHub-логину/почте.
5. Установите **GitHub Desktop** (если ещё нет): https://desktop.github.com
6. В GitHub Desktop: **File → Clone Repository** → выберите `schedule-service`
   → укажите папку на компьютере → **Clone**.
7. Скопируйте содержимое папки `schedule-service` (которую я вам прислал:
   `frontend/`, `bot/`, `schema.sql`, `README.md`) внутрь склонированной папки
   репозитория, заменяя автоматически созданный `README.md`, если нужно.
8. В GitHub Desktop появятся изменённые файлы слева. Внизу впишите сообщение
   коммита, например `Initial project structure`, нажмите **Commit to main**,
   затем **Push origin**.

🔲 **Разработчик 2 (если в паре):**

1. Примите приглашение в почте или на github.com/notifications.
2. В GitHub Desktop: **File → Clone Repository** → склонируйте `schedule-service`
   себе.
3. Вверху нажмите **Current Branch → New Branch** → назовите
   `feature/frontend` → **Publish branch**.
4. Дальше все изменения в `frontend/` разработчик 2 делает именно в этой ветке.

> Если делаете лабораторную в одиночку — просто работайте в `main`, но для
> зачёта по чек-листу желательно всё равно создать ветку `feature/frontend`,
> закоммитить туда фронтенд отдельно и слить через Pull Request — так
> наберётся нужная история коммитов и будет виден Pull Request.

## Часть 3. Сайт (Frontend → Vercel)

✅ Уже сделано: `frontend/config.js` содержит ваши `SUPABASE_URL` и
`SUPABASE_ANON_KEY`.

🔲 **Деплой на Vercel:**

1. Зайдите на [vercel.com](https://vercel.com) → войдите через GitHub.
2. **Add New → Project**.
3. Выберите репозиторий `schedule-service`.
4. В настройках проекта:
   - **Root Directory** — укажите `frontend` (важно! иначе Vercel попытается
     собрать весь репозиторий, а не только папку сайта).
   - **Framework Preset** — оставьте `Other` (это обычный статический
     HTML/CSS/JS без сборки).
   - **Branch** — если используете `feature/frontend`, выберите её в
     настройках (Vercel по умолчанию берёт `main`; ветку можно поменять в
     Settings → Git после первого деплоя, либо сразу выбрать при импорте).
5. **Deploy**.
6. Через 30–60 секунд Vercel даст вам ссылку вида
   `https://schedule-service-xxxx.vercel.app` — откройте её, должен
   загрузиться список групп и расписание.

Если сайт открылся, но список групп пустой или ошибка в консоли браузера
(F12 → Console) — пришлите скриншот, посмотрим.

## Часть 4. Telegram-бот

✅ Уже сделано:
- Бот создан через @BotFather, токен получен.
- `bot/.env` заполнен (`BOT_TOKEN`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`).

🔲 **Запуск бота у себя на компьютере:**

1. Установите **Node.js**, если ещё нет: https://nodejs.org (LTS-версия).
2. Откройте терминал (командную строку) внутри папки `bot/`.
3. Выполните:
   ```bash
   npm install
   ```
   Дождитесь, пока установятся зависимости.
4. Затем:
   ```bash
   npm start
   ```
5. В консоли должна появиться строка `Бот запущен...`.
6. Откройте вашего бота в Telegram, нажмите **Start** или отправьте `/start`.
7. Выберите группу кнопкой.
8. Проверьте команды `/today` и `/now`.

> Важно: пока в терминале запущен `npm start`, бот работает. Если закрыть
> терминал — бот остановится. Для лабораторной этого достаточно (не
> обязательно держать бота онлайн 24/7 на отдельном сервере), но если
> хотите, чтобы он работал постоянно — можно развернуть его позже на
> Railway.app, Render.com или подобном сервисе (это уже опционально,
> заданием не требуется).

🔲 **Закоммитьте код бота** (Разработчик 1, в ветке `main`):
1. В GitHub Desktop появятся файлы из `bot/` (кроме `.env` — он не должен
   попасть в коммит благодаря `.gitignore`, который я уже добавил).
2. Проверьте, что в списке изменений **нет** файла `bot/.env` — если он там
   есть, значит `.gitignore` не сработал, не коммитьте его руками с токеном
   внутри.
3. Commit → **Push origin**.

## Часть 5. Pull Request и слияние веток

🔲 (Актуально, если работаете в паре или сделали отдельную ветку
`feature/frontend`):

1. Зайдите на GitHub в репозиторий `schedule-service`.
2. Появится баннер **Compare & pull request** для ветки `feature/frontend` —
   нажмите его.
3. Проверьте, что сравниваются `main ← feature/frontend`, добавьте описание,
   **Create pull request**.
4. Разработчик 1 (или вы сами) заходит во вкладку **Pull requests**,
   открывает PR, проверяет изменения и нажимает **Merge pull request** →
   **Confirm merge**.

## Часть 6. Финальная проверка (чек-лист сдачи)

🔲 Пройдите по каждому пункту:

1. **Git:** в репозитории минимум 4 коммита, фронтенд слит через Pull Request
   (не просто запушен напрямую в `main`).
2. **Единая база:** зайдите в Supabase → Table Editor → `schedule` → измените
   `subject_name` у любой пары ПО-33 → обновите страницу сайта (F5) и
   отправьте боту `/today` — новое название должно появиться в обоих местах
   без изменения кода.
3. **Логика `/now`:** в разное время дня спросите `/now` у бота (или
   посмотрите блок "Сейчас" на сайте) — должно корректно показывать:
   - "Идёт N пара: ..." во время занятия,
   - "Перемена. Следующая пара в ..." в перерыве,
   - "На сегодня все пары закончились" после последней пары.
